# AGENTS.md — Project Guidelines & Architectural Contracts

## 1. Project Overview
This repository implements an end-to-end transit data engineering, predictive modeling, and multi-hop AI intelligence platform for **SEPTA** (Southeastern Pennsylvania Transportation Authority). It serves two workflows:
1. **Operations & Policy Copilot:** Natural-language Text-to-SQL (AST-guarded) + Hybrid RAG (`pgvector` + Postgres `tsvector` RRF) over SEPTA ridership, OTP, detours, weather, and FY26–27 operating budget PDFs.
2. **Commuter & Airport Trip Predictor:** Empirical delay distribution ($p_{50}$, $p_{90}$), crowding index, and `LightGBM` delay forecasting for origin–destination trips (including Temple University to PHL Airport).

## 3. Database Schema & Data Contracts
The database runs on PostgreSQL 16 with the `pgvector` extension enabled.

### 3.1 Dimension Tables
- `dim_routes`: `route_id` (PK, e.g., 'AIR', 'BSL', 'MFL', 'PAO', 'BUS_23'), `route_short_name`, `route_long_name`, `route_type` (0=Trolley, 1=Subway, 2=Regional Rail, 3=Bus), `mode_category`, `description`.
- `dim_stops`: `stop_id` (PK, e.g., 'STOP_TEMPLE', 'STOP_30TH', 'STOP_PHL_A'), `stop_name`, `stop_lat`, `stop_lon`, `wheelchair_boarding`, `zone_id`, `is_major_hub`.
- `dim_date`: `date_key` (PK, DATE), `day_of_week` (1-7), `day_name`, `is_weekend`, `is_holiday`, `fiscal_year`, `fiscal_quarter`. (SEPTA FY begins July 1).

### 3.2 Fact Tables
- `fact_otp`: On-Time Performance aggregated daily by route. Columns: `date`, `route_id`, `scheduled_trips`, `on_time_trips`, `delayed_trips`, `cancelled_trips`, `otp_percentage`, `average_delay_seconds`.
- `fact_ridership`: Hourly passenger volume and vehicle crowding. Columns: `date`, `route_id`, `stop_id`, `hour_of_day`, `boardings`, `alightings`, `unlinked_passenger_trips`, `load_factor`.
- `fact_detours`: Active and historical disruptions. Columns: `route_id`, `start_datetime`, `end_datetime`, `reason`, `detour_type`, `impact_score` (1-5).
- `fact_weather`: Philadelphia regional weather. Columns: `date`, `hour_of_day`, `temp_f`, `precipitation_inches`, `snowfall_inches`, `wind_speed_mph`, `weather_condition`.

### 3.3 Hybrid Vector Store
- `budget_document_chunks`: Stores chunked Operating Budget and Capital Program PDFs. Columns: `id` (UUID), `document_title`, `fiscal_year`, `page_number`, `section_header`, `content`, `embedding` (vector(1536)), `tsv_content` (generated tsvector). Indexed via HNSW (`vector_cosine_ops`) and GIN (`tsv_content`).

## 4. Security & AST Guardrail Contract (`agent/sql_guard.py`)
All SQL generated by the Text-to-SQL node MUST be parsed through `sqlglot` and pass AST validation prior to execution:
1. **Read-Only Invariant:** Statement must be `exp.Select` or `exp.Union`. All mutation statements (`Insert`, `Update`, `Delete`, `Drop`, `Alter`, `Truncate`, `Command`) are strictly blocked.
2. **Table Whitelisting:** Only tables in `ALLOWED_TABLES` (`dim_routes`, `dim_stops`, `dim_date`, `fact_otp`, `fact_ridership`, `fact_detours`, `fact_weather`, `budget_document_chunks`) or declared CTE aliases are permitted.
3. **Command Chaining Prohibition:** Multiple statements separated by semicolons are rejected.
4. **Dangerous Function Blocking:** Calls to functions such as `pg_sleep`, `pg_terminate_backend`, `dblink`, or file I/O functions trigger immediate security rejection.
5. **LIMIT Injection:** If no `LIMIT` clause is present, the guard injects `LIMIT 100`. If `LIMIT > 500` is requested, it is automatically clamped to 500.
6. **Least Privilege Execution:** The query is executed using the `readonly_copilot` database role with a 10-second statement timeout.

---

## 5. Hybrid RAG & Reciprocal Rank Fusion (`agent/rag_node.py`)
Multi-hop document retrieval uses Reciprocal Rank Fusion (RRF) to combine dense vector search with sparse full-text search:
$$RRF\_score(d) = \sum_{m \in \{dense, sparse\}} \frac{1}{60 + rank_m(d)}$$
- Dense retrieval uses cosine distance over 1536-dimensional embeddings.
- Sparse retrieval uses PostgreSQL `ts_rank_cd` over the `tsv_content` generated tsvector.
- Results are ranked by descending RRF score and injected into the LLM context with precise page and section citations.

---

## 6. Trip Predictor & Commuter Guidance (`models/`)
Predicts delay and crowding for origin-destination transit corridors:
1. **Empirical Distribution ($p_{50}, p_{90}, p_{95}$):** Calculated per OD pair, day of week, peak vs off-peak time, and weather impact factor.
2. **LightGBM Delay Forecasting:** Trained on temporal features, weather metrics, corridor OTP, and active detour flags to predict expected delay in minutes.
3. **Commuter Departure Buffer:** Recommends departure time buffers based on $p_{90}$ tail risk and transfer safety margins to ensure 95%+ probability of timely arrival for flights at PHL Airport.

---

## 7. Testing & Evaluation Benchmarks (`evals/` & `tests/`)
- Golden benchmark set `evals/golden_set.json` contains 50 test queries (15 SQL, 15 RAG, 10 Hybrid, 5 Predictor, 5 Adversarial).
- Automated evaluation harness `evals/run_eval.py` must achieve 100% interception on adversarial injection attempts and report latency percentiles ($p_{50}$, $p_{90}$, $p_{99}$).
